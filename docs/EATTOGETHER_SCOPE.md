# EatTogether implementation scope

Current scope as of 23 October 2026 includes restaurant management. See [CONCEPT_ALIGNMENT.md](CONCEPT_ALIGNMENT.md) for implemented rules and agreed variations.

## Seats and eligibility

Each account reserves one EatTogether seat; friends Join separately. Ordinary bookings retain party size. Existing multi-diner records are preserved and can explicitly shrink to one seat. Verified adult eligibility and optional immutable age/gender preferences apply to discovery and Joins. Seeded Singpass identities are fictional; only credential login works.

Slots have a minimum, a maximum table size and a shared seat pool (`discountedSeats`, falling back to capacity for existing slots). New seed slots offer two tables' worth of seats, using synthetic restaurant limits. Ordinary bookings and Events share that pool under the same row lock. Each Event represents one table and stays within the maximum table size. Full-price bookings continue to occupy physical seats; removing the discount does not free their inventory.

Diner Event creation holds the minimum seats; Restaurant Event creation holds its entire configured table capacity. Additional Joins use the Event hold or free pool inventory. Displayed Event Capacity is bounded by the table limit and its own hold plus free seats. New Events close at Cutoff, two hours before dining. Cutoff records the maximum headcount; later Joins replace departures rather than increasing that snapshot. A diner must Join an eligible existing Event with room before creating another at that slot. An account cannot hold two active Event seats at the same slot.

Hidden Events expose no identifiers or participant data, while free seats at that slot remain bookable. Public participants expose names, exact ages and gender; birth dates, reliability records, reports, blocks, individual price choices and feedback are private. Participant cards show role, age and gender rather than repeating the single-seat count. Own memberships/history remain accessible. The six verified demo identities are aged 21–26 in October 2026. These fictional birth dates represent preverified identity data; the MVP does not retrieve data from Singpass.

Discovery has one restaurant collection with at most three cards per page and a Restaurant view / Map view toggle. Each venue contains a compact EatTogether section; the grid and map share the same Event information and one-at-a-time navigation. Counts consistently show Restaurants and matching EatTogether Events. Cuisine, price-band, minimum-discount and EatTogether availability filters apply to both views. Discounts are checked separately for ordinary slots and Events: a high-discount ordinary slot cannot qualify a lower-discount Event for the EatTogether filter. For you stays a restaurant-only popup, opened from the right of the search toolbar. Legacy Event-list links open restaurant discovery with the Events filter selected.

Booking details remain exclusively in Bookings. Profile contains identity, reliability/settings and notification history. The bell contains unread notifications; marking one as read removes it from the bell but keeps it in history. Both feeds use the same three-item pagination and render the latest 100 visible notifications supplied by the existing API. The reliability policy remains available through an information tooltip.

## Timing and reservations

| State               | Behaviour                                                                                                                                                                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Waiting for diners  | Before Cutoff, hold at least the minimum. Confirmation is automatic at minimum; falling below it makes an existing booking pending.                                                                                                            |
| Confirmed           | After Cutoff, Joins replace departures within the recorded Cutoff headcount, pool and table limits. Requalification reuses the booking reference.                                                                                              |
| Action needed       | At Cutoff, a short Event releases unused Held Seats. Each member accepts full price or declines without penalty before dining time. Joins close.                                                                                               |
| Full price          | Accepted members retain a full-price reservation. Unanswered choices expire at dining time. No discount is shown.                                                                                                                              |
| Last Call           | A late departure drops a confirmed Event below minimum. Nearby eligible diners receive in-app invitations. Remaining members can Leave without penalty. Refill restores the discount and booking; otherwise full price applies at dining time. |
| Cancelled / Expired | Inventory is released. Started confirmed/full-price reservations remain in history, with membership changes closed.                                                                                                                            |

Host departure in a Diner Event hands over to the earliest member, using user ID to break timestamp ties. An empty Diner Event cancels. The Host interface offers Leave, with a Handover explanation, rather than whole-Event cancellation. The older cancellation endpoint remains for compatibility. An empty Restaurant Event remains discoverable until Cutoff; its business Host does not occupy a diner seat. It can be withdrawn only while empty. The lifecycle runs every 30 seconds and on authenticated requests; detail reads and mutations reconcile their Event under its slot lock. Restart catches up due transitions without duplicate bookings/notices.

## Reliability and social tools

A confirmed late Leave after Cutoff requires acknowledgement and records a private strike, deduplicated per account/Event/reason. Three strikes within 90 days suspend new EatTogether creation and Joins for seven days; ordinary booking remains available. Last Call, full-price and blocked-diner departures are penalty-free. Restaurant-recorded no-shows apply the same policy after dining starts. Correcting a no-show to Attended removes that no-show strike and recalculates the rolling count and suspension. Attendance and reliability remain private to the diner and the assigned restaurant's operational roster; other diners cannot see them.

The notification bell contains persisted confirmations, member changes, Handover, cancellation, Cutoff, Last Call and reliability updates. Waiting Events send at most one reminder per Singapore calendar day, including creation day. Nearby invitations require an optional Profile neighbourhood within 5 km, using a static local coordinate catalogue. There is no GPS lookup, email, SMS or delivery while the app is closed. Stale/ineligible Last Call invitations are hidden.

Chat opens once confirmed, including an accepted full-price reservation. Current members and the Restaurant Host of a Restaurant Event can read/send. Merchants cannot access Diner Event Chat. Cancelled/expired Chat is read-only; leaving removes access. The latest 200 messages appear as plain text, with blocked authors hidden. Safety options are available on other diners' messages as well as participant cards and unsafe Feedback answers. Restaurant Hosts can also be reported or blocked. Blocking requires a confirmation that explains future Event exclusion and penalty-free departure.

Report and Block are inside Events. Reports are private pending records; no moderation console or automatic punishment exists. Blocking is silent, hides future Events containing either account, and can be undone in Profile. Existing shared reservations remain accessible for safe departure.

Optional private Feedback opens after the scheduled start of a confirmed/full-price booking. It asks about overall experience, safety, social experience, meal, dining again and suggestions, with three keyboard-accessible star scales. A diner must attest attendance; the form remains a self-report, separate from the merchant's attendance record. Recorded no-shows cannot submit Feedback or receive new Feedback invitations. A once-per-Event in-app invitation arrives two hours after scheduled start. That delay is a reminder convention, not proof of completion. Skipping has no reliability effect. Unsafe answers expose report/block. Only the submitting diner can read/edit a response. Restaurant Hosts see aggregate ratings and response counts for their own Restaurant Events, never individual responses or free-text suggestions.

For you uses dining mood and optional typed location (within 15 km), with no cuisine dropdown. Food spellings and menu synonyms are normalized; typed cuisines/menu items constrain semantic ranking. Weak semantic matches are rejected using an absolute score floor and relative band, with at most six results. Fresh searches do not hide previously saved/skipped restaurants. Saved venues are marked, and advancing past one does not remove it from the shortlist. Cosine similarity is not shown as a confidence percentage.

Explicit navigation, filters, pagination, menus, modals and restaurant Event disclosures have short transitions. Background refreshes preserve focus/selection without repeated entrance effects. Reduced-motion preferences disable motion, including explicit mobile scroll assistance.

## Interface and deferred scope

The same application has separate Diner and Restaurant login views selected above the forms. Eight seeded business accounts use name@business.com and password123, one per venue. The backend derives role and restaurant ownership from the session; switching the login view is not an authorization mechanism. Corppass badges are fixed demo verification fixtures. Registration, recovery and real identity sign-in remain disabled.

The restaurant dashboard contains Reservations, EatTogether and Slots, with a dining-date selector and three records per page. Merchants can opt their restaurant or individual slots out of new EatTogether Events, edit unallocated future slot limits/offers, and create Restaurant Events with a custom minimum, table capacity and discount. Existing allocations protect slot prices and seat limits. Optional immutable age/gender filters require an explicit Themed Event. Whole-table holds release unused seats at Cutoff. Confirmed Restaurant Events share the diner lifecycle and keep the restaurant as Host.

Attendance opens at or after the booked dining time, for the assigned restaurant only, including Diner Events at that venue. Attended/No-show records are idempotent and correctable. If excluding no-shows leaves fewer diners than the Event minimum, the reservation becomes full price; corrections can restore the agreed Event offer but cannot override a full-price acceptance made at Cutoff. Unknown attendance is not treated as a no-show. No completion metrics are inferred from these records.

Ordinary booking, Event detail and restaurant management share a Recommended menu popup. Menu dishes/prices are local presentation fixtures, with SGD prices rounded in cents and original prices beside the selected slot/Event discount. An Event at full price shows no discount. This is a price preview, not ordering, payment or live Eatigo pricing. Cutoff has a heading, Singapore date/time and a visible explanation; redundant remaining-seat and missing-diner counts are removed from Event detail.

Restaurants form one main collection with nested EatTogether Events, shared grid/map views and availability filters. For you is a restaurant-only popup. Book | EatTogether lives inside restaurant booking. My bookings has private reservations left and Events right, two per page. Profile retains notification history without duplicating booking details. Chat, Feedback, dining area and blocked diners are collapsed disclosures.

Interactive mock verification is paused; preverified demo accounts remain.

Deferred: real Singpass/Corppass/UEN checks, working registration/password recovery, moderation/appeals, payments, mutual Connections and validated completion/KPI dashboards. Report moderation remains explicitly on hold.
