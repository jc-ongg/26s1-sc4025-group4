# Table 5 usability walkthrough

This guide maps the non-verification tasks in the current report's Section 5.5 to the working application. It is a facilitator guide, not a participant script or a record of study results. All practice identities, reservations and historical ratings are fictional.

## Prepare a session

Start the app with `docker compose up -d --build --wait`, then run `npm run demo:prepare` from the repository root. The second command resets only the explicitly named `usability-` practice slots, their associated Events/reservations and the named practice accounts' safety/reliability/notification state. Unrelated slots, reservations and the original six diner identities are retained. An entirely empty daily slot can be adopted as practice inventory; occupied slots are never taken. Prepare immediately before each test session or rehearsal; reloading a page does not reset it.

Use http://localhost:3000. For phone testing, use the laptop's LAN address and port 3000 on the same reachable network. Use separate browser profiles/private windows or devices when keeping two accounts signed in; ordinary tabs share the session cookie. The generated dates and IDs are saved to ignored `tmp/usability/scenarios.json`. Dates are calculated at preparation time; Thursday/Wednesday tasks use the next eligible evening, moving one week later if that time already has reservations. The app's clock is never changed.

## Agreed timing and scope

- One account reserves one EatTogether seat. Ordinary bookings retain party size.
- Before Cutoff, membership may grow to the table/pool limit. Cutoff records the headcount, releases unused holds and closes new Event creation. Afterwards, Joins may replace departures but cannot increase that recorded headcount. A confirmed Event below minimum opens Last Call; refill retains the reservation reference. If it remains short at dining time, full price applies. Last Call departures are penalty-free.
- A short unconfirmed Event at Cutoff offers individual full-price acceptance or penalty-free decline. Unanswered choices expire at dining time. Empty Restaurant Events release their entire hold at Cutoff.
- Feedback opens after scheduled dining time, requires an attendance attestation and remains optional. This is not a verified completed-meal metric. Recorded no-shows cannot submit it.
- Verification uses preverified fictional accounts for now. Interactive mock verification is on hold. Credential login works; actual Singpass/Corppass login, registration and recovery do not.
- Connections, physical table management, human report moderation, payments and an analytics dashboard are outside these twelve tasks.

## Recording results

`backend/src/table-five.test.ts` executes the ten non-verification task paths against the isolated CI database. Other integration tests cover authentication/ownership, races, inventory, immutable filters, expiry, strikes, feedback privacy and no-show corrections. These checks establish program behaviour; they do not establish usability success rates.

Use participant codes and actual observations to complete the report's SEQ, SUS, task-completion and issue-log tables. Preloaded historical Feedback is demonstration data, never participant evidence.
